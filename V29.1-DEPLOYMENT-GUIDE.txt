V29.1 GitHub / Vercel 部署指南（第一次使用也可以照做）
========================================================

适用场景：

- 你已经有 GitHub 仓库和 Vercel 项目。
- V29 已经部署成功，但 Vercel 的 AI 线框图预览显示破损。
- 你要升级到 V29.1，同时保留原来的域名和环境变量。

重要结论：

V29.1 不需要删除 AI_LINKUANG_ACCESS_CODE，也不需要重新创建 Vercel 项目。
只要更新 GitHub 仓库内容并让 Vercel 重新部署即可。

--------------------------------------------------------
第一步：备份当前 GitHub 版本
--------------------------------------------------------

推荐在 GitHub 仓库页面创建一个 Release 或 Tag，例如：

v29-before-wireframe-fix

如果不会创建 Tag，也可以在 Vercel → Deployments 中确认旧的 Production 部署仍然存在。
Vercel 会保留旧部署，升级失败时可以回滚。

不要删除 Vercel 项目，不要删除现有域名，不要删除 Environment Variables。

--------------------------------------------------------
第二步：正确解压 V29.1
--------------------------------------------------------

1. 在 Windows 中右键 V29.1 ZIP。
2. 选择“全部解压”。
3. 打开解压目录。
4. 当前目录应直接看到：

   vercel.json
   package.json
   index.html
   server.js
   start.bat
   api 文件夹
   src 文件夹
   styles 文件夹
   assets 文件夹

如果打开后还要再进入一个同名文件夹才能看到这些内容，说明上传层级不正确。
本 V29.1 ZIP 已按“根目录直接是项目文件”的方式打包。

你不需要手工创建 dist 文件夹。Vercel 部署时会执行：

node scripts/build-vercel.js

然后自动生成 dist。

--------------------------------------------------------
第三步：先在 Windows 本地检查
--------------------------------------------------------

1. 双击 start.bat。
2. 等待黑色窗口显示服务已就绪。
3. 浏览器会打开：

   http://127.0.0.1:8787/

4. 打开：

   http://127.0.0.1:8787/api/health

5. 检查内容中包含：

   "version": "V29.1"
   "buildId": "v29.1-wireframe-vercel-preview-fix-20260815"
   "runtime": "windows-local"

6. 本地生成一张 AI 线框图，确认预览和下载正常。

本地模式仍会把线框图片保存在：

data/v26/wireframe-history-assets

--------------------------------------------------------
第四步：更新 GitHub 仓库
--------------------------------------------------------

推荐方式：使用 GitHub Desktop

1. 打开 GitHub Desktop。
2. Clone 你现在的仓库到电脑。
3. 把 V29.1 解压目录中的全部文件复制到仓库根目录，选择覆盖同名文件。
4. 确认仓库根目录可以直接看到 vercel.json 和 package.json。
5. 检查 Changes，确认没有 .env、真实 API Key 或 Token。
6. Commit Summary 填写：

   fix: upgrade to V29.1 wireframe preview

7. 点击 Commit to main。
8. 点击 Push origin。

如果只使用 GitHub 网页：

1. 进入仓库根目录。
2. 点击 Add file → Upload files。
3. 把 V29.1 解压后的项目内容拖入上传区域，而不是拖入外层文件夹。
4. 提交到 main。
5. 将旧的 V29-CHANGELOG.txt、V29-DEPLOYMENT-GUIDE.txt、V29-MODIFIED-FILES.txt、V29-REGRESSION-CHECKLIST.txt 从仓库根目录移除；它们在 V29.1 包中已归档到 docs/history/V29。

注意：GitHub 网页更新大量嵌套文件比较容易漏文件，优先使用 GitHub Desktop。

--------------------------------------------------------
第五步：确认 Vercel 自动部署
--------------------------------------------------------

1. 打开 Vercel。
2. 进入原来的 ai-linkuang 项目。
3. 点击 Deployments。
4. GitHub main 更新后，应出现一个新的部署记录。
5. 等待状态变成 Ready。

如果没有自动部署：

1. 进入 Project Settings → Git。
2. 确认连接的是正确仓库和 main 分支。
3. 回到 Deployments。
4. 在最新部署右侧菜单中选择 Redeploy。

不要再次创建一个新的 Vercel 项目，否则会得到新的域名和另一套环境变量。

--------------------------------------------------------
第六步：环境变量保持不变
--------------------------------------------------------

进入：

Vercel Project → Settings → Environment Variables

至少保留：

AI_LINKUANG_ACCESS_CODE
  你的小范围访问口令。不要删除。

EVOLINK_API_KEY
  真实 EvoLink API Key，不加引号，不加 Bearer。

EVOLINK_BASE_URL
  https://api.evolink.ai/v1

如果需要对应功能，再保留：

COZE_API_TOKEN
PADDLEOCR_ACCESS_TOKEN

环境范围建议选择：

Production and Preview

如果修改了任何环境变量，必须重新部署后才会生效。

--------------------------------------------------------
第七步：检查 V29.1 是否真的上线
--------------------------------------------------------

1. 打开你的正式地址，例如：

   https://ai-linkuang.vercel.app/

2. 按 Ctrl+F5 强制刷新。
3. 页面标题应显示：

   V29.1 · 图灵线框工作台

4. 打开：

   https://你的域名/api/health

5. 输入访问口令后，检查健康信息：

   version = V29.1
   runtime = vercel-serverless
   persistence.wireframeHistory = browser-local
   persistence.wireframeAssets = provider-url

如果仍显示 V29，说明你打开的是旧部署、浏览器缓存或 GitHub 没有更新成功。

--------------------------------------------------------
第八步：专门验收 AI 线框图
--------------------------------------------------------

1. 打开 AI 线框生成。
2. 选择排版参考图。
3. 填写海报文案。
4. 点击生成 AI 线框图。
5. 等待生成完成。
6. 右侧图片应完整显示，不应出现破损图片图标。
7. 点击放大预览，应显示同一张图。
8. 点击下载当前图，文件应完整。
9. 点击下一步 AI 生图，线框图应能继续作为参考图。

进一步检查：

1. 按 F12。
2. 打开 Network。
3. 再生成一次线框图。
4. 搜索：

   wireframe-history/assets

5. V29.1 本次生成不应该出现新的该类图片请求。
6. 也不应该出现由 app_access_required 引起的线框图片 401。

旧 V29 中已经变成 /api/wireframe-history/assets/... 的浏览器历史没有保存原始 EvoLink 地址，无法完整恢复。V29.1 会自动清理这些失效记录；重新生成一次即可。

--------------------------------------------------------
第九步：理解当前历史限制
--------------------------------------------------------

V29.1 面向小范围测试：

- 同一浏览器可以保存自己的线框历史。
- 换电脑、换浏览器或清除网站数据后，线上线框历史不会同步。
- EvoLink 原始图片地址如果将来过期，旧历史也可能失效。
- Windows 本地版不受这一点影响，因为它会保存图片文件。

如果以后要多人共享、长期保存，应接入：

Vercel Blob / 阿里云 OSS / Cloudflare R2 / AWS S3

并使用数据库保存历史记录元数据。

--------------------------------------------------------
第十步：出现问题时回滚
--------------------------------------------------------

1. 打开 Vercel → Deployments。
2. 找到升级前状态正常的 V29 部署。
3. 打开右侧菜单。
4. 选择 Promote to Production 或 Rollback。

回滚不会删除 GitHub 的 V29.1 代码；确认问题后仍可重新部署。

--------------------------------------------------------
最终验收
--------------------------------------------------------

[ ] 页面显示 V29.1。
[ ] 访问口令仍然有效。
[ ] EvoLink Key 没有出现在浏览器或 GitHub。
[ ] AI 线框图预览完整。
[ ] AI 线框图下载完整。
[ ] AI 生图正常。
[ ] Windows start.bat 正常。
[ ] Vercel Analytics 正常。
[ ] Vercel 保留旧部署，可随时回滚。
