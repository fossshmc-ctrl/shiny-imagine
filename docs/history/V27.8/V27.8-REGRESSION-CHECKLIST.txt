V27.8 REGRESSION CHECKLIST
==========================

一、混合区域 Prompt
-------------------
[ ] 同时选择至少 3 个 OCR 区域。
[ ] 只修改其中一个文字区域的文案。
[ ] 点击微调生成。
[ ] 不出现其他区域“AI 修改指令没有进入最终生图 Prompt”。
[ ] 性能仪表从预检/流程交接继续进入压缩与上传。
[ ] 任务详情中的区域数量与已选区域数量一致。

二、15 区域场景
---------------
[ ] 保留约 15 个识别区域并全选。
[ ] 修改任意一个文字区域。
[ ] 本地回归前检 `missingInstructionRegionIds` 为空。
[ ] 每个区域名称或区域 ID 都能在最终 Prompt/结构化任务中找到。

三、自由添加区域
---------------
[ ] 新增一个自由文字区域，单独选择并应用。
[ ] 新增一个自由产品/装饰区域，与 OCR 区域混合选择并应用。
[ ] 自由区域 AI 修改指令非空。
[ ] 自由区域没有历史 Prompt 时仍能获得默认执行要求。
[ ] 从 V27.7 项目恢复的 custom_* 区域能够自动迁移。
[ ] 选择“保留人工区域”重新识别后，自由添加区域仍存在且仍为已选/可生成状态。

四、文案和实时参数
-----------------
[ ] 修改文案后 AI 修改指令包含原文到新文的替换要求。
[ ] 拖动/缩放区域后实时坐标继续更新。
[ ] 人工补充要求不会被实时参数覆盖。
[ ] 恢复原文时只移除文字替换要求，不删除其他人工要求。
[ ] 在区域文本框中修改后不点“保存文案”，直接生成，最新草稿仍进入 Prompt。
[ ] 在“识别文案纠正”中修改后不点“保存纠正”，直接生成，最新草稿仍进入 Prompt。
[ ] 结构化 JSON 中包含转义换行时，回归前检不会误判指令缺失。

五、失败安全与计费
-----------------
[ ] 人为构造缺失指令时，本地回归前检在压缩/上传前停止。
[ ] 错误信息列出具体缺失区域。
[ ] 本地前检失败不出现 task_id，不提交 `/images/generations`。
[ ] 正常生成只创建一次计费 POST；后续仅查询同一 task_id。

六、V27.4–V27.7 回归
--------------------
[ ] 5 分钟完整诊断缓存和 60 秒 Credits 缓存有效。
[ ] 两张参考图保持 2 路并发上传。
[ ] 连续两轮生成使用独立 sessionId/generationId。
[ ] 180 秒软阈值后继续查询同一 task_id。
[ ] 回归检测弹窗位于智能区域工作台上方。
[ ] 下载确认弹窗可见，远程结果通过本地代理下载。

七、Windows 发布包
------------------
[ ] 双击 start.bat 可启动。
[ ] `/api/health` 返回 V27.8 和正确 Build ID。
[ ] `/api/micro/health` 返回 micro-adjust-v27.8。
[ ] 页面、脚本和样式使用 `?v=27.8`。
[ ] API Key、PaddleOCR Token、Coze Token 为空。
[ ] 包内不存在 __pycache__、.pyc、运行日志和临时测试文件。
[ ] SHA256SUMS.txt 与外部 ZIP SHA256 校验通过。
