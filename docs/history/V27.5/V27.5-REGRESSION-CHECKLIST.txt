B. 复现问题的关键验收：连续两次微调
------------------------------------
[ ] 第一次选择区域并点击“微调生成”，仪表从预检进入流程交接、压缩/合并、上传和 provider task。
[ ] 第一次生成完成后再次对同一图片/同一区域发起第二次微调。
[ ] 第二次运行创建新的 sessionId 和 generationId。
[ ] 第二次不继承第一次的 generating、taskId、阶段耗时或错误。
[ ] 第一轮延迟到达的 performance 事件不能覆盖第二轮仪表。
[ ] 第二次 preflight 完成后在约 3 秒内进入 sync/compress，或明确失败；不得无限停留在 preflight-only。
[ ] 连续运行期间没有重复的 `/v1/images/generations` 计费 POST。

C. 直接交接与 acknowledgement
-----------------------------
[ ] region workbench 不查找或调用 `[data-adj-ai-run].click()`。
[ ] 区域 apply 仅负责同步数据，随后调用 `__V275_START_MICRO_ADJUST__()`。
[ ] 生成处理器在第一次 await 前写入 `microRunAcknowledgedAt`。
[ ] generationId 不一致时交接立即失败。
[ ] 缺少生成处理器时立即提示“未提交计费任务”。
[ ] 处理器未 acknowledgement 时立即返回 `micro_handoff_not_acknowledged`。
[ ] acknowledgement 未写入 micro channel 时立即失败，不发送 provider POST。
[ ] 成功 acknowledgement 后 handoffStatus=accepted。

D. 计费请求门禁
--------------
[ ] 浏览器端 generationActive=false 时阻止 `/api/micro/images/generations`。
[ ] generationId 与 active generationId 不一致时阻止请求。
[ ] handoff 不是 accepted 时阻止请求。
[ ] Node 服务缺少 `X-Micro-Handoff-Acknowledged: 1` 时返回 409。
[ ] Python 服务缺少 `X-Micro-Handoff-Acknowledged: 1` 时返回 409。
[ ] Node/Python CORS allow-headers 均包含 X-Micro-Handoff-Acknowledged。
[ ] 失败或超时后不自动重新提交计费 POST。

E. busy、完成与陈旧状态清理
---------------------------
[ ] 上一任务真实仍在运行时，第二次点击明确提示 busy，而不是静默等待。
[ ] busy 拒绝不会创建第二个 provider task。
[ ] 成功后 `aiBusy=false`、`microRunActive=false`。
[ ] 失败后 `aiBusy=false`、`microRunActive=false`。
[ ] handoff-failed 后状态可再次点击重试。
[ ] 已无执行 Promise 且超过 210 秒的 stale session 可被恢复。
[ ] 仍有真实 Promise 的任务不会因 stale recovery 被强制并发重提。
